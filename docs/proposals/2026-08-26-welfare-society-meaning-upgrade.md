# 福利型社会·人人寻找意义：升级提案

日期：2026-08-26  
状态：提案（未实施，不含任何已完成声明）

## 背景与核心判断

项目书 V4.8 第十章规划了"意义闭环"：意义只能在"选择—行动—反馈—再选择"中形成，系统不替用户定义意义。这与"人生的意义就是一直在寻找意义"同构——寻找过程本身就是意义形成的场所，而不是通往某个终点的过渡。

代码已为该理念备好底座：`meanings` / `hypotheses` / `experiments` 数据模型（`backend/src/routes/data.ts`）、八阶段蒸馏流水线含反例检索与用户门控（`backend/src/services/distillation/pipeline.ts`）、"时位势应变中"变化内核（`src/ai-native/reasoning/changeKernel.ts`）、L0–L3 分层记忆（ADR-0001）、工具终极消亡与自主能力增长率北极星。

**本提案把这条已蕴含的线，从"有真实长期目标的首发 persona"扩展到福利型社会中的每一个人。** 当基础收入、转岗与退出劳动力市场成为普遍状态，大量用户恰恰处于无目标或目标失焦状态——他们是最需要"寻找意义支架"的人群，也是当前首发漏斗明确排除的人群。

## 差距分析（六处缺口）

1. **漏斗门槛**：首发要求"有真实长期目标"；无目标者没有入口。
2. **意义模型无时间维度**：`meanings` 是静态 `direction` 列表，无方向变化史，无法表达"一直在寻找"。
3. **搜索过程不被记为成就**：放弃一个方向在现有模型中近似失败，与"寻找即意义"相悖。
4. **生活数据适配器全部待实现**（contract-complete / adapters-pending）：蓝领、平台劳动者等非知识工作者的输入依赖低摩擦传感器而非打字，这是全民覆盖的关键短板。
5. **陪伴连续性缺失**：意义搜索以年计，当前无"离开—回来"的再进入设计。
6. **硬件门槛**：three.js 系全量打包、无低端机降级，与"全社会适配"目标冲突。

## 升级方向

### P0-A 意义罗盘（Meaning Compass）

- 数据模型：`meanings` 增加 `phase`（exploring / focusing / paused / graduated）、`startedAt` / `endedAt`、`transitionReason`；旧数据迁移默认 `focusing`。
- 意义漂移图：用变化内核六算子呈现方向演变史（何时起、何时转、当时的位与势），只呈现事实与用户自己写下的理由。
- 转向即蒸馏：结束或转向一个方向时，记录"这段探索教会我什么"，作为 L2 情境方法入库；放弃 = 收获。
- Guardrails：系统不为方向排序优劣、不打分、不判吉凶；转向只能由用户触发；漂移图不暗示"应该坚持"。

### P0-B 探索者模式（无目标者入口）

- Onboarding 增加"我不知道要什么"路径：不要求预设长期目标即可进入。
- 前两周以零摩擦记录为主（文字自述 + 生活信号），随后复用蒸馏流水线 `candidate → counterSearch → userGate` 阶段，从微小证据生成候选方向。
- 候选方向明确标注为"工作假设"，用户可"不像我"一键否决（复用 userGate 纠正通道）。
- Guardrails：不推送"你应该……"；无目标状态不被表述为问题或缺陷；探索者可随时转入常规漏斗，反之亦然。

### P1-A 生活数据适配器落地

- 优先 Health Connect 与 Android 使用统计（契约层已就绪，补原生模块）；理由：非知识工作者的输入依赖传感器而非打字。
- 界面仍遵守现有边界：授权开关不得显示为"已同步数据"。

### P1-B 毕业与回归

- 自主能力增长率从口号变为可审计指标：先定义测量（如用户决策中系统代劳比例的下降、用户主动纠错的频率），**约束条件：不得与使用时长正相关**，防止指标退化为留存工具。
- 毕业建议：指标达阈值时主动提示可导出个人方法并卸载（工具终极消亡的可操作形态）。
- 回归再进入：超过 90 天未用后回来，基于 L3 生成"这些年你已成为谁"简报；不追问离开原因，不制造愧疚。

### P2-A 孪生体轻量化

- 用 `React.lazy` / 动态 import 拆分 three / @react-three 系 avatar 模块；低端机降级为 2D 镜像，不静默丢失功能声明。

### P2-B 同路人社区（谨慎，默认关闭）

- 隐私分级下的匿名"个人方法谱系"导出与对照；不做排行榜、不做社交比较。
- 触发条件：先有 P0 / P1 的长期用户研究数据。

## 实施顺序与验收原则

- 顺序：P0-A → P0-B → P1 → P2；每项另立实施计划（对齐 `docs/plans/` 格式）。
- 全程保持项目不变量：系统对人的理解永远是可质疑、可纠正、会过期的工作假设；不占卜、不说教、不诊断；用户主权优先。
- 验收要点：新字段有迁移与回滚路径；漂移图与探索者模式有 E2E；探索者入口不降低既有漏斗；增长率指标通过"与使用时长不相关"检查。
