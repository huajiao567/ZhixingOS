# 生活数据、自适应数字孪生与开源清理实施计划

日期：2026-08-26  
状态：已完成

## 目标

在不伪造已接入能力、不静默降级 3D 的前提下，建立手机、穿戴、电脑与饮食数据的统一扩展边界；让已确认的数据通过可解释、可衰减、可撤回的规则微调 3D 数字孪生；同时把历史报告与生成物归并成适合 GitHub 阅读和维护的少量权威文档。

## Step 1：建立连接器与生活信号协议

- Output：`src/ai-native/connectors` 中的连接器能力、授权、游标同步、来源和标准化生活信号类型。
- Output：保留 Health Connect/小米导出、Android 使用统计、ActivityWatch、饮食照片/条码、iOS 对应能力的明确接口和可用性要求。
- Test：类型检查；连接器注册表的唯一 ID、权限范围和隐私默认值测试。

## Step 2：建立自适应外观推导器

- Output：把已确认的睡眠、压力、餐后负荷、能量平衡与体重趋势推导为黑眼圈、疲劳、紧绷和克制的体型变化。
- Guardrails：候选饮食不生效；单餐不改变长期体型；压力不生成医学诊断；陈旧数据衰减；用户可关闭、纠正和清空。
- Test：熬夜、持续趋势、单餐、压力、过期、低置信度、未来时间戳、禁用适应等单元测试。

## Step 3：接入 3D 渲染与现有输入

- Output：VRM 眼下疲劳层、身体宽度微调、肩颈紧绷与表情权重共同响应自适应状态。
- Output：用户文字自述可生成有来源的本地生活信号；外部连接器今后使用同一入口。
- Test：渲染参数严格限幅；基础身份和用户确认外观不被自动覆盖；Web/Native 共用相同状态。

## Step 4：扩展数据主权界面与后端权限

- Output：增加手机使用、电脑使用、饮食营养三类权限；授权范围写明连接器、仅摘要和孪生用途。
- Output：撤回采集与删除历史仍分离；新增来源可独立删除并触发派生数据重算。
- Test：前后端类型、Zod 校验和运行时契约测试。

## Step 5：归并与精确清理

- Output：`docs/STATUS.md`、`docs/INTEGRATIONS.md`、`docs/TESTING.md` 成为当前权威说明。
- Delete：被上述文档完整吸收的日期型进展报告、重复测试报告、已执行历史计划，以及被 `.gitignore` 标注的 Playwright/截图/生物特征派生生成物。
- Keep：ADR、APK 真机说明、许可证选择、发布检查表、可追溯矩阵、可复现测试源码、设计参考原型和私有项目书。
- Test：README 不含失效链接；开源审计不发现敏感文件、二进制构建产物或被忽略的测试生成物。

## Step 6：全量验收

- Test：前端单元测试、后端单元/契约测试、前后端 TypeScript、Expo Doctor、Web production export、移动端 E2E、开源审计。
- Test：重新构建 APK，校验包名、SDK、签名和 SHA-256；构建失败必须保留真实错误，不以旧 APK 或二维占位冒充成功。

## 验收结论

- 连接器协议、来源级撤回/删除、自适应外观推导与真实 3D 渲染联动已完成；原生厂商适配器仍按真实状态标记为待接入。
- 重复日期报告、已执行旧计划、一次性诊断脚本和忽略的测试生成物已归并或清除，权威入口收敛到 `STATUS.md`、`INTEGRATIONS.md` 与 `TESTING.md`。
- Android SDK 36 四 ABI preview APK 已重新构建并通过 v2 debug 签名校验；最终哈希以 `ANDROID_APK_TEST.md` 为准。
