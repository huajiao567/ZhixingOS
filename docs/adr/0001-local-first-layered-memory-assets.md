# ADR-0001：本地优先的分层记忆资产与预算化召回

- 状态：Accepted
- 日期：2026-08-23
- 决策者：ZhixingOS maintainers
- 参考：[TencentDB Agent Memory](https://github.com/TencentCloud/TencentDB-Agent-Memory)（MIT）

## 背景

项目已有 `Evidence → Pattern → Experience → PersonalSkill → MetaPrinciple → PersonalModelVersion` 与 `TwinProfile`，但秘书仍按固定数量读取多类记录，缺少统一资产身份、问题相关性、总字符预算和召回回执。数据量增长后会出现上下文过量、候选认识越级使用、来源不透明与用户数据被当作提示指令等风险。

TencentDB Agent Memory 2.0 的有价值思想是：L0–L3 分层、原始来源可回查、关键词与向量混合检索、召回预算、资产所有权/可见性/绑定、版本与异步状态。其完整部署面向团队代理，需要 MemoryCore、MemoryHub、Proxy、数据库/向量能力和额外模型配置；直接嵌入移动端会破坏本项目的本地优先、低门槛和单用户数据主权目标。

## 决策

采用“兼容其思想的本地资产投影”，不复制其服务代码，也不把 TencentDB 作为运行依赖。

| ZhixingOS 层 | 当前来源 | 使用边界 |
|---|---|---|
| L0 来源记录 | 用户事件及其来源引用 | 只作可核验经历，不推断人格 |
| L1 原子认识 | 承诺、可反驳假设 | 受 R/D 服务契约和状态约束 |
| L2 情境方法 | 已保留模式、已观察/重复/验证经验、当前实验、PersonalSkill | candidate/stale/retired 不进入秘书上下文 |
| L3 长期核心 | 用户自述、已确认孪生特征、纠正边界、keep/watch 跨域原则 | 用户边界固定携带；候选特征不得伪装成稳定人格 |

实现不变量：

1. 先按 `user_id`、R/A/D/P 服务契约和纠正规则裁剪，再检索；禁止“先召回、后授权”。
2. 资产默认 `private`，只绑定当前 agent；每项携带 owner、layer、kind、sourceRefs、version、status。
3. 当前使用无外部依赖的中文二元组/拉丁词检索，结合证据质量、时效与层级排序；最多 16 项、单项 700 字、总计 5000 字、25ms 预算。最新 8 条用户纠正边界固定优先，完整历史仍由孪生版本保留，避免边界无限增长挤掉当前任务记忆。
4. 召回返回结构化 receipt：策略、资产 ID、层级计数、字符数、遗漏量、partial/reason、耗时。
5. 记忆与历史放入显式 data 标签；系统提示明确其不是指令，并转义标签字符，降低持久化提示注入风险。
6. 重要长期结论继续走现有用户审查、反证、纠正和版本机制；检索层不自行生成 Persona。

## 不采用的方案

- **直接部署 TencentDB 全套服务**：能力强，但引入团队租户、代理资产市场、云数据库与双模型配置，不适合作为大众移动端的默认基础设施。
- **把全部记忆拼入系统提示**：简单但不可扩展，也会放大隐私与提示注入风险。
- **当前即引入向量数据库**：现阶段语料规模和离线目标不足以抵偿运行复杂度；保留后端无关的资产契约，达到检索质量阈值后再加入 BM25 + embedding + RRF 适配器。

## 后果

正向：秘书按当前问题使用更少、更相关、可追溯的记忆；候选认识不会越级进入稳定人格；无需新增云服务即可离线运行；未来可替换检索后端而不改变上层资产契约。

代价：本地词面检索暂不能覆盖所有语义同义表达；L0 目前是事件而非完整对话日志；跨设备合并、向量召回和长期质量评测仍需后续实证。出现这些限制时必须显示为能力边界，不得伪装成已完成。
