# Governance

## Decision principles

Project decisions prioritize user agency, data portability, accessibility, reversibility, evidence quality and public benefit. Growth, engagement or model capability cannot override these principles.

## Roles

- Maintainers merge changes, manage releases and security responses.
- Contributors propose, implement, test and document changes.
- Domain reviewers may be requested for accessibility, security, privacy, health or legal-adjacent work.

Until a broader maintainer group is established, the repository owner has final merge responsibility. Significant decisions must still be documented with alternatives and dissent.

## Decision process

- Routine fixes use normal Pull Request review.
- Architecture, schema, licensing, telemetry, high-impact executors and governance changes require a public proposal and a reasonable comment period.
- Security incidents may be fixed privately first and documented after users can update safely.
- A rejected proposal should record the technical or ethical reason and conditions for reconsideration.

## Public-benefit guardrails

The project should maintain a usable no-cost core, avoid dark patterns and behavioral advertising, support export and self-hosting, and design for elderly, disabled and low-connectivity users. Community deployments must not present heuristic inferences as official eligibility, credit, employment, policing or medical judgments.

## Changing this document

Governance changes require a dedicated Pull Request labeled `governance`, a summary of impact on contributors and users, and explicit maintainer approval.
